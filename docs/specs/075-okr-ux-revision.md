# OKR-дашборд: ревизия вёрстки и UX — spec (issue #75)

## Why

На приёмке P3 (portal.bbm.academy/p/okr, issue #60) владелец дал пять пунктов
фидбека по вёрстке и UX. Канонический референс вёрстки — HTML-макет
`bbm/outputs/2026-07-22-okr-dashboard/deploy/index.html` (PRD BBMP-124: вёрстка
портала обязана ему соответствовать). Диагностика показала: все четыре
конкретных симптома — регрессии портирования прототипа в компоненты роута,
а не проблемы самого макета.

## Диагнозы (stage-1 разбор, для контекста)

1. **Белая рамка** — layout группы `(platform)` рендерит голые `<html><body>`
   без глобального reset'а: браузерный `body { margin: 8px; background: white }`
   даёт белую рамку вокруг `.okr-root`. В макете есть
   `body{margin:0;background:var(--paper)}` — при портировании строка потерялась.
2. **Клик по эпику уводит в Plane** — в `KrRow` заголовок обёрнут в
   `<a href={planeUrl}>` внутри `<summary>`: клик по тексту уходит по ссылке
   вместо разворота. В макете заголовки строк вообще не были ссылками.
3. **Вёрстка «едет» при hover** — hover-правило строки использует трюк
   `margin:0 -8px; padding-inline:8px; width:calc(100% + 16px)`. В макете
   строка была `<button>` (у кнопок браузерный `box-sizing: border-box`),
   в портале — `<summary>`/`<div>` (`content-box`): на hover контентная ширина
   реально растёт на 16px → текст переносится иначе, элементы прыгают.
4. **Шеврон приподнят** — вертикальная посадка глифа `›`
   (`transform: translateY(-1px)` + flex-выравнивание) не совпадает с базовой
   линией первой строки текста; требует точной подгонки в обоих состояниях
   (свёрнуто / развёрнуто-повёрнуто).

Проверено против оригинала в Claude Design (проект «BBM Academy Design
System», получен через DesignSync 2026-07-27):

- `okr_dashboard/OKR-дашборд Doctor.School.html` в Claude Design байт-в-байт
  идентичен локальному `design-export/okr-dashboard-doctor-school.html`
  (отличаются только переводы строк). CSS всех четырёх симптомов (reset
  body, строка-`<button>`, hover-трюк, шеврон) одинаков в оригинале, в
  `deploy/index.html` и отличается от портала ровно так, как описано выше.
  Заголовки строк/карточек не были ссылками нигде — ссылки в Plane добавлены
  при портировании в портал.
- Файл токенов `colors_and_type.css` (в репо отсутствует) получен и сверен:
  расхождения токенов с deploy/порталом — только документированное
  AA-затемнение (`--ink-3`, `--accent-ink`, `--accent-2-ink`,
  `--status-info-ink` темнее; приоритет bbm-public-website/tokens.css) —
  оставить как есть.
- **Находка:** `colors_and_type.css` нёс глобальные стили дизайн-системы,
  потерянные при инлайне токенов в deploy и не дошедшие до портала:
  `:focus-visible { outline: 3px solid var(--ink) … }` (обязательный
  видимый фокус, «never remove»), `::selection`, цвет ссылок. Возврат
  focus-visible/selection в scope okr-страницы включён в requirement 5.

## Requirements

1. Страница `/p/okr` — без белой рамки: фон `--paper` от края до края окна,
   как в референсе (reset `margin`/фона на уровне layout платформы).
2. Клик по **любому месту** строки KR с шевроном (включая текст заголовка)
   разворачивает/сворачивает список действий **на месте**; никакой навигации.
   Переход в Plane — отдельное явное действие: иконка-ссылка (↗) в строке,
   открывается в новой вкладке. Единообразно для строк KR, строк действий и
   заголовков карточек objectives: заголовок — не ссылка, рядом иконка.
3. Hover ни на одном элементе не меняет метрики строки: количество строк
   текста, переносы и положение элементов неизменны — меняются только
   фон/тень/цвет.
4. Шевроны выровнены по вертикали с текстом строки в обоих состояниях.
5. Постраничная сверка с `deploy/index.html` по состояниям: hover,
   развёрнуто/свёрнуто, длинные заголовки, узкие экраны (одна колонка
   ≤900px). Расхождения устраняются; сознательные отличия портала (данные
   из Plane вместо снапшота, баннеры stale/error, легенда с переносом,
   отсутствие owner-dropdown) фиксируются списком в PR. Сюда же — возврат
   потерянных глобальных стилей дизайн-системы из `colors_and_type.css`
   в границах okr-страницы: видимый фокус `:focus-visible` (клавиатурная
   навигация по строкам-`summary`) и `::selection`.
6. Ограничение: страница остаётся без клиентского JS (native
   `<details>/<summary>`), если какой-то пункт не потребует иного — тогда
   это отдельный checkpoint с владельцем до имплементации.

## Acceptance scenarios

Все — на живом стенде `https://portal.bbm.academy/p/okr` (вход через Zitadel).

1. Открыть страницу: фон мятный (`--paper`) до самых краёв окна, белой
   рамки/подложки вокруг контента нет.
2. Кликнуть по строке KR с шевроном — в любом месте, включая текст
   заголовка: список действий разворачивается на месте; повторный клик
   сворачивает; в Plane ничего не уводит.
3. Кликнуть по иконке ↗ в той же строке: открывается соответствующая
   задача в Plane в новой вкладке.
4. Провести мышью по строкам KR и карточкам: подсветка появляется, но ни
   одна строка текста не перескакивает, элементы не смещаются.
5. Посмотреть на шевроны рядом с текстом: сидят на одной линии с первой
   строкой заголовка, и в свёрнутом, и в развёрнутом состоянии.
6. Сузить окно до мобильной ширины: колонки складываются в одну, ничего
   не разъезжается и не обрезается.

## Out of scope

- Автообновление открытой вкладки (real-time) — при необходимости отдельная
  задача.
- Owner-dropdown из прототипа (в проде владельцы = assignee в Plane).
- Изменения модели данных, роллапа прогресса, светофора здоровья.
- Редизайн: направление BOLD «ПОП» / палитра «Лагуна» и структура экрана
  не пересматриваются — только приведение к макету.
