# Карта пути — файл данных

Страница **`/p/path`** портала («Карта пути») рисуется целиком из одного файла:
[`doctor-school.yaml`](./doctor-school.yaml). Базы данных, API и редактора нет —
**правка карты = правка этого файла + деплой**. Файл читается на каждый запрос;
если в нём ошибка, страница не рисует карту, а показывает список ошибок с
указанием, где именно (`tracks[2].nodes[1]: …`). Проверка формата — тот же код,
что в юнит-тесте `tests/unit/path-map-parse.spec.ts`, поэтому сломанный файл не
пройдёт и CI.

Что это за карта: вертикальная дорога от «Мы здесь» вверх к **маяку** (куда идём
и зачем). Треки — дороги к маяку. На дороге стоят **станции** (результаты),
**шлагбаумы** (что мешает) и **туман** (открытые вопросы). Внизу — пройденный
путь: снятые шлагбаумы с датами.

## Поля

### Верхний уровень

| Поле           | Обязательно | Что это                                                                 |
| -------------- | ----------- | ----------------------------------------------------------------------- |
| `title`        | да          | Название карты в шапке («Doctor.School»)                                |
| `started`      | нет         | Дата старта `ГГГГ-ММ-ДД` (настоящая дата календаря) — «старт 6 окт»     |
| `beacon.title` | да          | Маяк — формулировка цели                                                |
| `beacon.why`   | нет         | «Зачем» под маяком                                                      |
| `limits`       | нет         | Лимиты (ниже); по умолчанию 3 / 2 / 3                                   |
| `tracks`       | нет         | Список треков; пустой (или голое `tracks:`) — пустая карта с подсказкой |

`limits`:

| Поле                    | По умолчанию | Что делает                                                                       |
| ----------------------- | ------------ | -------------------------------------------------------------------------------- |
| `focus_tracks`          | 3            | Сколько треков может быть в фокусе. Больше — значок «фокус переполнен»           |
| `visible_stations`      | 2            | Сколько ближайших станций трека видно. Всё выше уходит в туман                   |
| `obstacles_per_station` | 3            | Сколько открытых шлагбаумов на одну станцию. Больше — подсказка «разбей станцию» |

### Трек (`tracks[]`)

| Поле     | Обязательно | Что это                                                                             |
| -------- | ----------- | ----------------------------------------------------------------------------------- |
| `id`     | да          | Латиница в нижнем регистре, цифры, дефис; уникален                                  |
| `title`  | да          | Название дороги                                                                     |
| `short`  | нет         | Короткое имя для вкладок на телефоне («Контент»); иначе `title`                     |
| `status` | нет         | `focus` (на дороге, по умолчанию) или `roadside` (на обочине)                       |
| `nodes`  | нет         | Узлы **снизу вверх**: первый — ближайший к «Мы здесь»; голое `nodes:` — пустой трек |

### Узел (`nodes[]`)

Общие поля: `id` (уникален на всю карту, не `beacon`), `type`, `title`,
`owner` (метка того, кто ведёт, например «ДС» — просто текст), `opens`.

| `type`     | Дополнительные поля                                  | Как рисуется                                                                                                             |
| ---------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `obstacle` | `done: ГГГГ-ММ-ДД` — шлагбаум снят; `tasks` — задачи | Жёлтый шлагбаум. С `done` — уходит вниз, в «Пройденный путь», с датой. С `tasks` — счётчик и поднимающаяся стрела        |
| `station`  | `because` — «потому что»; `confidence` — уверенность | Карточка станции. Без `because` — на обочине: «Станция без «потому что»»                                                 |
| `fog`      | —                                                    | Облако тумана: «Здесь пока неизвестно: …». Без `opens` дорога на нём обрывается; с `opens` идёт дальше, но «через туман» |

`confidence` станции: `known` — асфальт (по умолчанию), `hypothesis` — грунтовка
(пунктир), `unknown` — станция в тумане (размыта).

`opens` — `id` узла, который этот узел открывает (можно в другом треке), или
`beacon`, если узел ведёт прямо к маяку.

Названия (`title`, `short`) — текст; число вроде `title: 2026` читается как
текст «2026». Даты (`done`, `started`) должны существовать в календаре:
`2026-13-45` или `2026-02-30` — ошибка.

Неизвестное поле (например, опечатка `becuase:`) — ошибка: карта покажет, где
она. Это сделано нарочно, чтобы опечатка не съедала данные молча.

### Задачи шлагбаума (`tasks`)

У шлагбаума может быть список задач — что нужно сделать, чтобы он поднялся.
Задача может содержать подзадачи (`tasks` внутри задачи), вложенность — не
глубже 5 уровней (считая от шлагбаума). Поле необязательное.

| Поле    | Обязательно | Что это                                                                                                                                                                         |
| ------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title` | да          | Что сделать                                                                                                                                                                     |
| `done`  | нет         | `true` — сделано; дата `ГГГГ-ММ-ДД` — сделано в этот день; `false` или нет поля — не отмечено (задача с подзадачами всё равно считается сделанной, когда сделаны все подзадачи) |
| `owner` | нет         | Метка того, кто делает («ДС») — просто текст, как у узла                                                                                                                        |
| `link`  | нет         | Ссылка `http(s)://…` — например, на задачу в Plane; открывается в новой вкладке                                                                                                 |
| `tasks` | нет         | Подзадачи — список таких же задач                                                                                                                                               |

```yaml
- id: studio
  type: obstacle
  title: Довести студию до готовности
  opens: first-lesson
  tasks:
    - title: Свет и звук
      tasks:
        - { title: Купить петличные микрофоны, done: 2026-10-24 }
        - { title: Тестовая запись, link: 'https://…' }
    - { title: Монтажёр на поток, owner: ЕВ }
```

Как считается прогресс: **по задачам без подзадач** («листьям»). Задача с
подзадачами — это заголовок над ними, её саму счётчик не считает, иначе «4/7»
зависело бы от того, как задачи сгруппированы. `done` у задачи с подзадачами
закрывает их все; если у неё `done` нет (или `done: false`), она считается
сделанной, когда сделаны все подзадачи. То же правило — на уровне шлагбаума:
`done` у самого шлагбаума закрывает все его задачи, и у снятого шлагбаума
прогресс всегда полный, даже если какие-то задачи не отмечены.

Пустое `tasks:` (без списка) — то же, что задач нет. У задач нет `id`: файл
правят руками, а задачу находят по её месту в списке.

Как это видно на карте:

- на шлагбауме — счётчик «сделано/всего», например **4/7**; без `tasks` счётчика нет;
- полосатая стрела шлагбаума **поднимается** пропорционально прогрессу: 0% —
  опущена, 100% — поднята до упора (с `prefers-reduced-motion` — без анимации);
- клик по шлагбауму в режиме «Карта» открывает справа панель **«Что внутри»**:
  название, кто ведёт, что открывает, прогресс и дерево задач (первый уровень
  раскрыт, глубже — по клику). Закрыть — крестик или Esc; фокус возвращается на
  шлагбаум. На телефоне и планшете (до 1140px) панель открывается секцией под
  картой, а при закрытии страница возвращается к шлагбауму. У снятого шлагбаума с задачами панель
  открывается по клику на его строку в «Пройденном пути».

Снять шлагбаум (`done` у самого шлагбаума) по-прежнему нужно явно: 7/7 задач
поднимают стрелу до упора, но не переносят шлагбаум в «Пройденный путь».

## Как работает «Проверить путь»

В шапке переключатель **Карта / Проверить путь**. В режиме проверки любой блок
кликабелен — в том числе станции, свёрнутые в «Дальше туман», и снятые
шлагбаумы в «Пройденном пути»: от него карта идёт по цепочке `opens` вверх,
пока не дойдёт до `beacon`, и показывает справа цепочку звеньев и итог.

Дорога **доходит**, если цепочка закончилась на `beacon`. Итог называет самое
слабое место по пути:

- всё известно — «доходит»;
- есть станция-гипотеза — «доходит, по грунтовке»;
- есть станция `confidence: unknown` **или любой туман** (`type: fog` с `opens`)
  — «доходит через туман». Туман всегда снимает уверенность: это вопрос без
  ответа, даже если известно, куда он ведёт.

Дорога **обрывается** (разрыв), если:

- `opens` указывает на `id`, которого нет на карте;
- в цепочке станция без `because`;
- у узла нет `opens` (туман без `opens` — тоже разрыв: дальше дороги не видно);
- цепочка зациклилась.

Разрыв рисуется и в панели, и на самой карте — над блоком, где дорога
обрывается (в том числе над свёрнутым туманом и над снятым шлагбаумом).

Внизу панели — итог по каждому треку в фокусе (проверка от его ближайшего к
«Мы здесь» узла). Неизвестный `opens` **не считается ошибкой файла** — это
ровно то, что режим проверки должен показать.

## «Мы здесь», обочина, туман

- **«Мы здесь»** в каждом треке — граница между снятыми шлагбаумами (ниже, с
  датами) и всем остальным (выше).
- **Обочина** (правая панель): треки со `status: roadside` и станции без
  `because`.
- Выше `limits.visible_stations` ближайших станций трек сворачивается в туман
  «Дальше туман».

## Как попросить агента отредактировать карту

Достаточно сказать, что изменить, своими словами, и назвать файл. Примеры:

- «В `content/path-map/doctor-school.yaml` сними шлагбаум „Довести студию до
  готовности" сегодняшней датой».
- «Добавь в трек „Своя платформа" станцию „Эксперты продают курсы" с id
  `experts-sell-courses`, потому что „эксперты зарабатывают на платформе",
  открывает маяк» — это закроет намеренный разрыв в примере.
- «Отправь трек „Охват и подкасты" на обочину, а „Фарма-партнёры" выведи в фокус».

Агенту: правьте только этот файл, сохраняйте порядок узлов снизу вверх, `id` —
латиницей; после правки прогоните `pnpm test:unit -- path-map` — тест проверит,
что файл валиден. Изменения видны после деплоя портала.
