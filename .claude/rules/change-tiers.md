# Change tiers — Ship / Show / Ask

The procedure a change goes through is proportional to its risk. The tier is picked before work starts, from what the change does; the changed-file set sets a mechanical minimum the author may raise but never lower. Unsure → the higher tier. A request that turns out to need new logic is re-tiered, and the owner told, before the work continues.

Owner decisions: 2026-11-24, recorded in the body of #597 (option "a", the ds-platform tiers ported); 2026-11-25, recorded in #606 (the presentational Ship class, as in ds-platform).

| Tier | Qualifies                                                                                                                                                                                                                                                                                                                                                                                                         | Procedure                                                                                                                                                                                                                                                                                    |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ship | prose, typos, copy and small presentational tweaks: only ship paths (below) — plain docs prose at any size, new or modified; copy modules and view-layer sources modified, no new/removed/renamed one, ≤80 changed lines together; or **test-only** — a PR that changes only tests                                                                                                                                | the lead authors it inline only within `.claude/rules/lead-delegation.md` §1 (≤1 file, one attempt), a larger Ship goes to an implementer; worktree + branch as usual; no separate review; no live stand; green CI; Stage-B is the owner's decision in chat                                  |
| Show | ordinary UI and logic: a new state or behaviour inside an existing feature, a new view file, a route file, any logic module; no Ask path                                                                                                                                                                                                                                                                          | normal dispatch; independent review and the iteration-end gate stay; the owner's «принято» is given on agent-captured Playwright screenshots in the PR, with no stand visit. **The lead's UX-sanity pass and the `UX-record` stay mandatory on Show** (`.claude/rules/design-process.md` §2) |
| Ask  | auth / IdP, money (the finance module), member PII (152-FZ: `src/lib/member/**`; the member admin screens are presentational and not Ask), the outbound site-dispatch integration, the dev-DB seed, DB migrations and schema, `infra/` and deploy, `.claude/` and `tools/` (instructions, guards, tooling), CI, dependencies and config, API and server endpoints, the Payload content contract, new specs / ADRs | the full cycle in `.claude/skills/task-cycle/SKILL.md`: the owner's go, independent review, the iteration-end gate, live-stand acceptance for an owner-visible change                                                                                                                        |

**Declaration.** Exactly one PR-body line `Change-tier: Ship|Show|Ask — <reason>` (case-insensitive; the bold label `**Change-tier:**` is accepted). A Ship or Show line must give a real reason (`n/a`, `tbd`, a `<placeholder>` is none); Ask needs none. A missing, duplicated or malformed line is a finding.

**Mechanical minimum** — `tools/lint/lib/change-tier.mjs`, the one classifier every gate reads; its path lists are the definition and are not restated here. In short: Ask when any changed path (or rename source) is structural — `tools/`, `.claude/`, `.github/`, `infra/`, `deploy/`, `scripts/`, `design-source/`, `AGENTS.md`/`CLAUDE.md`, a `package.json`, the lockfile, a config file, `middleware.*`, `src/migrations/`, `src/lib/platform/db/` — a test there included; or when a non-test file is on an auth/IdP, finance, member (`src/lib/member/`), site-dispatch (`src/lib/site{Dispatch,Sync}.ts`), seed (`src/seed/`), API/endpoint, Payload-contract (`src/{collections,globals,fields,hooks}/`) or `docs/{adr,specs}/` path. Otherwise Show when a non-test file is not a ship path, a non-prose file is added/removed/renamed, a prose doc or a test is removed (a test also when renamed), or non-test, non-prose changes (copy and view-layer sources together) exceed 80 lines. Otherwise Ship. An empty or incomplete changed-file set is Ask. `tests/helpers/` is not a test path (it seeds and deletes users in the shared dev DB), so it is at least Show.

**Ship paths** (an allowlist; tests are exempt): plain prose — `docs/**/*.md` outside `docs/{adr,specs}/`, `DEBT.md`, a `README.md` — at any size and when new; a copy module (`copy.ts`, `*-copy.ts`, `copy/*.ts` under `src/`) and a render-capable view-layer source (`isUiSourcePath`: a `*.tsx` / `*.css` under `src/` — app screens, `src/modules/**` views, the `src/ui/` kit), both capped and never new. A UI-shaped file that carries routing or server behaviour is never a ship path: a Next.js route or special file `app/**/{page,layout,route,template,default,loading,error,not-found,global-error,global-not-found,forbidden,unauthorized,opengraph-image,twitter-image,icon,apple-icon}.*`, a `server/` or `actions/` segment, an `*action*` source, a `.d.ts`. Logic in `*.ts` (models, `lib/`, hooks) is at least Show, so a tweak that also adds logic floors at Show; a tweak on an Ask path (auth, finance, API, the Payload contract, `src/lib/member/`, `design-source/`) stays Ask. The classifier reads paths, not content: a server component's data fetch inside a plain `*.tsx` is the author's tier call (unsure → the higher tier), and the reviewer-free merge of a verified Ship is the price accepted for it, as in ds-platform. Canon docs (`docs/specs/`, `docs/adr/`, the rule and skill files under `.claude/`) are prose too but keep their Ask floor on purpose: they are decisions and procedure, not copy.

**Routing.** Every gate routes by the **effective** tier — `resolveTier` in the classifier: max(declared, minimum), and Ask when the line is missing or invalid, so an undeclared PR never buys a lighter procedure. Each gate re-proves the minimum from the PR's changed-file set itself; the body line alone is never trusted.

- `pnpm pr:land` refuses a declaration below the minimum, lifts the review requirement only for a verified Ship (the review-free class, `.claude/skills/task-cycle/SKILL.md` stage 4), and names the acceptance the tier owes.
- `pnpm lint:stage-b` routes the Stage-B record: a verified Ship UI tweak needs only the owner's chat decision recorded as a `GO` (no `UX-sanity:` record), Show accepts the owner's `Stage-B: GO (screenshots) — <owner, date>`, Ask only the live-stand `GO — <owner, date>` (`.claude/rules/design-process.md` §2; the acceptance protocol is task-cycle stage 5).

**Enforcement.** The `change-tier` guard (`pnpm lint:change-tier <PR>`, job in `pr-body-guards.yml`, row in `docs/ci-guardrails.md` §5) reports a missing/duplicate/malformed line and a declaration below the minimum. Its CI job stays WARN, an early in-PR hint: the merge gate already refuses a declaration below the minimum.
